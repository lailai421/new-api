# 在 new-api 中实现提示词审计

## Goal

将 `sub2api` 已有的“提示词审计”能力迁移并适配到 `new-api`。当管理员开启提示词审计后，用户的受支持 AI 请求必须先通过审计才能转发至上游渠道；审计不通过时由 `new-api` 在上游调用前拦截，以降低违规提示词进入渠道的风险。

## Requirements

- 系统提供可启停的提示词审计能力。
- 审计模式仅包含“关闭”和“同步阻断”两种状态，不提供只记录不阻断的异步审计模式。
- 审计生效范围支持“全部分组”和“指定分组”两种配置；指定分组使用 `new-api` 现有的稳定分组字符串标识，只有命中范围的用户请求进入同步审计门禁。
- 分组范围配置必须采用明确匹配，不得因空列表、分组不存在或配置解析失败而意外扩大或缩小审计范围；配置无效时按失败关闭策略阻止受影响请求绕过门禁。
- 审计开启后，受支持的用户请求必须在请求上游渠道前完成审计。
- 首版必须覆盖 `new-api` 所有包含提示词或用户输入文本的请求入口，包括常规 HTTP Relay、OpenAI Realtime WebSocket、Midjourney、视频任务及通用 Task Plugin；不得存在可绕过同步审计的协议入口。
- 对长连接或多阶段协议，每一段可能被发送至业务上游的新增用户输入都必须先完成同步审计，不能只审计握手请求或首帧内容。
- 审计通过时保持原有请求转发链路；审计拒绝或发生按策略应拦截的异常时，不得调用业务上游渠道。
- 审计采用失败关闭策略：全部 Guard 节点不可用、超时、响应非法、运行配置降级、协议缺少明确提取契约或必要事件写入失败时，均不得调用业务上游渠道。
- 管理员能够在“安全与限制”菜单下配置、查看或维护提示词审计能力；具体配置项以 `sub2api` 现有能力和 `new-api` 架构适配结果为依据。
- 每条审计事件必须保存完整、未脱敏的**用户提示词**（该请求中全部 user 输入），管理员能够在事件详情中查看用户原文。不得把客户端人设、system、developer、assistant 或工具结果写入事件密文。见子任务 `09-04-prompt-audit-user-scan`。
- 用户提示词属于高敏感审计数据，只能通过受保护的专用管理接口访问；不得出现在普通用户接口、通用配置响应、应用日志或错误响应中。
- 用户提示词必须原样、无截断地保存，并采用应用层加密落库；Root 管理员通过事件详情接口按需解密查看，事件列表只返回脱敏预览。
- 审计事件默认永久保留；管理员可以配置按天计算的保留期，系统自动清理超过保留期的事件及其完整提示词，同时支持管理员手动删除历史事件。
- 保留期配置为“永久”时不得执行自动删除；修改保留期后，清理任务按新策略处理既有数据，并记录不包含提示词原文的管理操作审计日志。
- 系统提供“保存通过事件”开关且默认开启；开启时保存 Pass、Block 和 Error 全部审计事件，关闭时仅保存 Block 与 Error 事件，以便管理员在审计完整性与数据库容量之间进行明确取舍。
- 多轮对话提供“仅审计最新用户输入”开关，但默认关闭。默认送审与默认落库均为该请求中全部用户输入（含历史 user），不包括 system、developer、assistant、工具结果和客户端内置人设。由子任务 `09-04-prompt-audit-user-scan` 修正。
- 即使启用“仅审计最新用户输入”，也只进一步缩小送审范围为最新一轮 user，不得退回扫描或落库人设全文；事件仍保存该请求全部用户提示词，并记录实际送审范围。无用户输入的 Allow 不写事件。
- 方案需覆盖后端请求链路、配置与持久化、管理 API、前端菜单与页面、国际化、权限、安全、可观测性及测试。
- 实现需遵守 `new-api` 的 Router → Controller → Service → Model 分层、三数据库兼容、前端 i18n 以及项目现有安全约束。

## Acceptance Criteria

- [ ] 管理员关闭提示词审计后，现有受支持请求链路及上游调用行为不受影响。
- [ ] 管理员开启提示词审计后，受支持请求仅在审计通过时调用业务上游渠道。
- [ ] 管理员能够选择对全部用户分组生效，或仅对指定分组字符串生效；命中与未命中范围的请求行为均有回归测试。
- [ ] 系统不存在“已开启但仅异步记录、未经审计即放行”的配置状态或执行路径。
- [ ] 常规 HTTP Relay、Realtime WebSocket、Midjourney、视频任务及通用 Task Plugin 中的所有提示词入口均经过同步门禁，并有逐类回归测试证明拒绝请求不会触达业务上游。
- [ ] Realtime 等长连接协议中的后续用户输入帧必须逐次审计，拒绝后不得将对应内容转发至业务上游。
- [ ] 审计拒绝时返回稳定、可识别的错误响应，并确认业务上游渠道未被调用。
- [ ] 审计服务异常、超时及配置错误均按照最终确定的失败策略处理，且有可追踪日志。
- [ ] Guard 不可用、响应非法、配置降级、协议缺少提取契约和必要事件写入失败时均返回稳定 503 错误，且业务上游调用和预扣费次数为零。
- [ ] “安全与限制”菜单中存在提示词审计管理入口，页面文案覆盖项目全部前端语言。
- [ ] 管理 API 仅允许具备相应管理权限的用户访问，敏感配置不会在响应或日志中泄露。
- [ ] 审计事件详情能够向授权管理员展示完整、未脱敏的用户提示词（不含人设/工具结果）；普通用户及非授权管理接口无法获取该字段。
- [ ] 超过 64 KiB 的用户提示词仍能完整加密保存和逐字符解密还原，不因数据库方言或字段类型被截断。
- [ ] 无论同步审计成功、拒绝还是异常，完整提示词均不会被写入应用日志、错误消息或审计服务节点探测结果。
- [ ] 默认配置下审计事件永久保留；配置有限保留天数后，过期事件能够被自动清理，未过期事件不受影响。
- [ ] 授权管理员能够手动删除指定审计事件，删除后对应完整提示词不可再通过管理接口获取，且删除操作可追踪但不记录提示词原文。
- [ ] “保存通过事件”默认开启；关闭后 Pass 事件不落库，但 Block 与 Error 事件及其完整提示词仍按保留策略保存。
- [ ] 默认扫描并保存该请求全部用户输入（不含人设/system/工具结果）；管理员启用“仅审计最新用户输入”后，只改变送审文本范围，落库仍为该请求全部用户提示词。见 `09-04-prompt-audit-user-scan`。
- [ ] system、developer、user、工具结果、附件文本和各协议特有提示词字段均有确定的提取规则与回归测试，不通过无差别遍历任意 JSON 字符串实现。
- [ ] Task Plugin 通过明确的审计文本路径契约声明规范化请求中的提示词字段；审计开启时缺少有效契约的提交请求失败关闭。
- [ ] 后端单元/集成测试与前端构建、i18n 校验通过；如涉及数据库变更，完成 SQLite、MySQL、PostgreSQL 的真实数据库验证矩阵。

## Out of Scope

- 本轮不编写或修改业务代码。
- 不直接复制 `sub2api` 中与提示词审计无关的模块。
- 不审计业务上游生成的响应内容；本功能只处理发送给业务上游的客户端输入。
- 不对图片、音频、视频等二进制内容执行视觉或语音内容审核；只审计协议中明确提供的文本、字幕、转写和提示词字段。
- 不改变受保护的项目身份、品牌、元数据或归属信息。

## Trellis Task Breakdown

本父任务拆分为以下 Trellis 子任务：

1. `09-03-prompt-audit-core`：领域契约、加密与 Guard 核心。
2. `09-03-prompt-audit-storage-api`：配置和事件持久化、清理、启动接线与 Root 管理 API。
3. `09-03-prompt-audit-http-relay`：标准 HTTP Relay 与 Midjourney 门禁。
4. `09-03-prompt-audit-realtime`：Realtime WebSocket 逐帧门禁。
5. `09-03-prompt-audit-task-plugin`：视频及通用 Task Plugin 门禁。
6. `09-03-prompt-audit-web-console`：安全与限制菜单下的管理界面。
7. `09-03-prompt-audit-integration-check`：全链路、前后端及三数据库验收。
8. `09-04-prompt-audit-llm-classifier`：LLM 分类器后端。
9. `09-04-prompt-audit-cyber-abuse`：Cyber Abuse 分类与启发式。
10. `09-04-prompt-audit-user-scan`：默认只扫描用户输入，排除客户端人设。

依赖顺序为 `core → storage-api → 协议接入与 web-console → integration-check`。`web-console` 只依赖管理 API 契约冻结；HTTP Relay 与 Task Plugin 需协调共享的 `controller/relay.go`。
